# Grounded Theory

> **Essence:** A systematic qualitative method for building theory *from* data rather than testing prior theory on it — through iterative cycles of coding, constant comparison, theoretical sampling, and memoing until categories saturate.

## Overview

Grounded theory (GT) was a declaration of independence: Glaser and Strauss argued in 1967 that qualitative data could generate rigorous theory, breaking the monopoly of hypothetico-deductive verification. The method's engine is a tight loop: **collect data → code it → compare incidents to incidents and codes to codes (constant comparison) → let categories and their properties emerge → sample next data specifically to develop the emerging theory (theoretical sampling) → write memos that lift codes toward concepts → repeat until new data stops adding properties (theoretical saturation)**. The output is a substantive theory — often a core category or basic social process that organizes the rest ("how people manage X").

Three moves define competent GT. **Coding in stages**: open coding (fracture data into incident-level labels), axial coding (relate categories: conditions, actions/interactions, consequences — Strauss & Corbin's paradigm), selective coding (integrate around the core category). **Constant comparison**: every new incident is compared against everything coded so far, so categories are refined by data, not imposed. **Memoing**: the written thinking trail where the analyst records hunches, definitions, and model sketches — memos, sorted and elaborated, become the theory's first draft.

GT has three living schools, and method papers must declare one. **Glaserian (classic)**: emerge, don't force; the analyst's only job is to stay open (Glaser's *Theoretical Sensitivity*, 1978; his slogan "all is data"). **Straussian (Strauss & Corbin)**: more procedural scaffolding — coding paradigm, conditional matrix — helpful to novices, accused by Glaser of "forcing" theory. **Constructivist (Charmaz)**: acknowledges the researcher co-constructs data and theory; favors gerunds (action-focused codes like "feeling invisible") and reflexivity.

GT is the right tool when the field lacks theory about a process (How do newcomers actually learn in online communities? How do clinicians really decide under alert fatigue?) and the researcher can iterate data collection. It is the wrong tool when theory exists to test, when data collection can't iterate, or when "grounded theory" is invoked as a license for undisciplined description — the most common abuse.

## Origin & History

- **1967:** Glaser & Strauss, *The Discovery of Grounded Theory* (Aldine) — written during their dying-patients study (*Awareness of Dying*, 1965); founded the method.
- **1978:** Glaser, *Theoretical Sensitivity* — the classic-school manual.
- **1990:** Strauss & Corbin, *Basics of Qualitative Research* — procedural school; 1992 Glaser's public break (*Basics of Grounded Theory Analysis: Emergence vs Forcing*).
- **2006:** Kathy Charmaz, *Constructing Grounded Theory* — constructivist school; now dominant in much contemporary practice.
- Today GT (or "GT-informed" coding) is the most cited qualitative approach across sociology, nursing, IS, HCI, and management.

## Core Concepts & Key Terms

| Term | Definition |
|---|---|
| Open coding | Fracturing data into incident-level labels, line by line. |
| Axial coding | Relating categories via the paradigm: causal conditions, context, strategies, consequences (Strauss & Corbin). |
| Selective coding | Integrating categories around the core category into a storyline/theory. |
| Constant comparison | Comparing incident↔incident, incident↔code, code↔code continuously. |
| Theoretical sampling | Choosing the NEXT data to collect based on what the emerging theory needs. |
| Theoretical saturation | New data no longer adds properties/variation to categories. |
| Memoing | The analyst's written thinking trail; the theory's nursery. |
| Core category / basic social process | The central concept that organizes the theory. |
| Theoretical sensitivity | The analyst's cultivated ability to see what matters in data. |
| Emergence vs forcing | Glaser's charge against procedural over-scaffolding. |

## When to Use / When Not to Use

**Use when:**
- No adequate theory exists for a process/phenomenon and you want to build one.
- You can iterate: collect–analyze–collect again (theoretical sampling is not optional in strict GT).
- The phenomenon is about action/process (how people do X over time), not just themes about a topic.
- You can commit to line-by-line engagement with rich qualitative data.

**Don't use when:**
- A testable theory already exists (use hypothetico-deductive designs, [case-study-research.md](case-study-research.md) for theory-testing, or surveys/experiments).
- Data collection cannot iterate (fixed dataset with no follow-up possible — do thematic/content analysis instead, honestly labeled).
- You only need themes for a report (GT's machinery is for theory-building; thematic analysis is the lighter honest choice).
- "Grounded" is being used as a synonym for "I read some transcripts" — reviewers will (rightly) punish it.

## Process & Steps

1. **Enter the field with a general wonderment, not hypotheses.** A broad question ("how do X manage Y?"), no literature-imposed framework (the classic-school stance; constructivists allow sensitizing concepts, declared). *Artifact: research posture note.*
2. **Collect initial data** (interviews, observations, documents — "all is data"). *Artifact: first corpus.*
3. **Open-code** line by line; use gerunds; stay close to data. *Artifact: open codes + codebook start.*
4. **Constant comparison + memoing** continuously: refine codes into categories with properties; record every analytic idea as a memo. *Artifact: memos + category definitions.*
5. **Theoretical sampling**: analyze gaps in emerging categories → decide whom/what to sample next → collect → code. Loop 4–5 (typically several cycles). *Artifact: sampling decisions log.*
6. **Axial/selective coding**: relate categories; identify the core category; build the storyline. *Artifact: category relationship map / conditional matrix.*
7. **Saturation check**: new data yields no new properties; document the evidence. *Artifact: saturation note.*
8. **Sort memos, write the theory**: the core category, its sub-processes, conditions and consequences; ground every claim in data quotes. *Artifact: substantive theory + write-up.*
9. **(Constructivist add-on) reflexivity statement**: your role in constructing the data/theory.

## Techniques, Tools & Deliverables

- Line-by-line coding discipline; in-vivo codes (participants' own words).
- Memo banks; memo sorting as theory assembly.
- CAQDAS tools (NVivo, ATLAS.ti, MAXQDA, or plain spreadsheets) — tools serve comparison, not the reverse.
- Theoretical sampling logs; saturation evidence tables.
- **Deliverables:** codebook with definitions, category scheme, core category + process model, memo archive, theory narrative with data grounding.

## Strengths & Limitations

| Strengths | Limitations |
|---|---|
| Builds genuinely new theory where none exists | Labor-intensive; line-by-line coding of large corpora is slow |
| Systematic: auditable moves, not impressionism | Easy to do badly — "GT" as cover for loose description |
| Theory stays empirically anchored (quotes to concepts) | Saturation is a judgment call; often claimed, rarely evidenced |
| Iterative design follows the data's leads | Requires access to iterate; slow ethics/IRB cycles can break the loop |
| Three schools offer entry points for different temperaments | School wars confuse novices; mixing schools incoherently is common |

## Worked Examples & Case Studies

- **Glaser & Strauss, *Awareness of Dying* (1965):** the original study — how hospital staff and patients manage (non-)awareness of dying; the theory of awareness contexts; GT's founding exemplar.
- **Strauss et al., chronic illness work (*The Discovery of Grounded Theory* lineage):** trajectory theory of chronic illness management — classic substantive theory.
- **Charmaz's chronic-illness identity work:** constructivist GT exemplar (e.g., "Good Days, Bad Days", 1991).
- **IS/HCI:** GT-derived process theories of online community participation, software-team practices, etc. — standard contemporary usage.

## Variants & Related Methodologies

- **Classic (Glaserian), Straussian, Constructivist (Charmaz)** — declare your school.
- **Dimensional analysis / situational analysis** (Clarke) — postmodern extensions.
- **Thematic analysis / qualitative content analysis** — lighter alternatives when theory-building isn't the goal (don't mislabel them GT).

## Agent Adaptation

### Suitability for agent execution

**Medium.** The mechanical half — line-by-line coding, constant comparison at scale, codebook maintenance, saturation tracking, quote retrieval — agents do faster and more consistently than tired humans, and they never skip the boring transcripts. The interpretive half — sensing what matters, the creative leap to a core category, and the reflexive judgment of the constructivist stance — is where agents need human steering, and where their training-data priors actively *pull toward conventional framings* (the opposite of emergence). Best pattern: agents as tireless coding engines and comparison machines under a human theorist who owns category creation and the core-category decision. Also note: agents cannot do the fieldwork itself (interviews, observation) — data still comes from humans.

### Recommended multi-agent workflow

| Role | Responsibility |
|---|---|
| Human researcher | Owns the emerging theory: category creation, core-category decision, theoretical sampling directions, memos' analytic content. |
| Analyst (coding agent) | Open-coding with gerunds, quote-anchored; proposes (never finalizes) category merges; constant-comparison diffs per new document. |
| Domain Expert (persona) | Challenges interpretations from the field's perspective; supplies sensitizing context. |
| Critic / Red Team | Audits: codes forced into prior frameworks? saturation claims supported? memo-to-code traceability? drift across batches? |
| Synthesizer | Maintains codebook, category maps, comparison tables, saturation evidence; drafts theory skeleton from human-approved memos. |
| Verifier | Every code/theme traces to verbatim quotes; quote accuracy checked against transcripts. |

### Agent pipeline

1. Ingest (human) → transcripts/documents batch.
2. Code (Analyst) → `codes.jsonl` [doc, line_ref, gerund_code, quote, memo_suggestion].
3. Compare (Analyst + Synthesizer) → comparison report vs existing codebook; proposed merges/splits → human adjudicates.
4. Theorize (human, aided by Synthesizer's category maps) → memos; theoretical sampling directives.
5. Stress-test (Critic) → forcing audit, saturation evidence check, drift check.
6. Iterate 2–5 across batches until human declares saturation with evidence.
7. Assemble (Synthesizer) → theory skeleton with quote grounding → human writes the theory.

### Prompt templates

```text
SYSTEM: You are a grounded-theory coding assistant (constructivist style). Code this transcript
segment line by line with GERUND codes that stay close to the data ("waiting for approval",
"managing impressions"). For each code: the verbatim quote, the line reference, and one sentence
on what action/process it captures. Do NOT import external theory or frameworks; do NOT summarize
— fracture. Flag segments where you sense something analytically interesting but cannot name it
(mark as "sensitizing puzzle" for the human researcher). Transcript: {{segment}}
```

```text
SYSTEM: You are the constant-comparison engine. Existing codebook: {{codebook}}. New codes:
{{new_codes}}. For each new code report: (a) identical to an existing code (merge candidate),
(b) a new PROPERTY/variant of an existing category (which one, what variation it adds), or
(c) genuinely new (provisional category proposal). For (b), state what range of the category
this incident extends. Output a structured comparison table. Never merge silently — every merge
is a proposal for the human researcher.
```

```text
SYSTEM: You are the Critic auditing a grounded-theory analysis. Codebook history: {{codebook_log}}.
Memos: {{memos}}. Audit for: (1) FORCING — codes that import prior theory rather than emerge
(find the quote that fails to support them); (2) SATURATION THEATER — categories claimed
saturated with thin or redundant evidence; (3) ORPHAN CODES — codes never compared or developed;
(4) DRIFT — code definitions that quietly changed across batches. For each finding cite the
evidence. This audit protects emergence; be unsparing.
```

### Tools & data requirements

Transcript/text storage with line references, a structured codebook store, diff/comparison tooling; no web tools needed (data is primary); CAQDAS export/import where humans also code.

### Quality checks, failure modes & mitigations

| Failure mode | Detection | Mitigation |
|---|---|---|
| Forcing (priors overwrite data) | Critic forcing audit + quote fidelity | Gerund discipline; human owns category creation |
| Code inflation (1000 one-off codes) | Codebook growth curve | Mandatory comparison/merge proposals per batch |
| Fake saturation | Critic saturation audit | Saturation evidence = categories + last-N-documents-no-new-properties record |
| Quote fabrication/misquoting | Verifier against transcripts | All codes quote-anchored; audit samples |
| Batch drift (coding style changes) | Critic drift check | Versioned codebook with definitions; re-code sample |
| Agent becomes the theorist | Human review of category maps | Hard rule: agents propose, humans dispose |

### Human-in-the-loop checkpoints

1. Category creation/merge decisions.
2. Core category selection (the theory's spine).
3. Theoretical sampling directives.
4. Saturation declaration and final theory narrative.

### Inputs & outputs (chaining contract)

**Inputs:** qualitative corpus (interviews/fieldnotes/documents — from [ethnography.md](ethnography.md) or interview studies); researcher posture/school declaration.
